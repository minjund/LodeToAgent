## 상세 발견

### 1. 카피라이팅 — 4/4

- `renderer/i18n-messages.js:1497-1503`의 홈 문장은 시스템 상태와 사용자 책임을 한 번에 말한다.
- “전체 작업”, “실시간 흐름”, “확인 요청”은 상태 분류를 짧고 행동 중심으로 표현한다.
- `renderer/app-management.js:463-469`가 실제 판단 개수에 따라 제목을 바꿔 정적인 마케팅 문구가 되지 않는다.

### 2. 시각 체계 — 4/4

- `renderer/styles-philosophical.css`는 기존 DOM·이벤트 계약을 유지한 채 판단(order 2), 실시간 흐름(order 3), 계정 한도(order 4)로 정보 위계만 재구성한다.
- 최신 데스크톱 캡처에서 메인 에이전트, 실행 중 작업, 완료 작업을 한 시선 흐름으로 읽을 수 있다.
- 서브에이전트와 실행 작업은 서로 다른 상세 drawer로 열려 정보가 섞이지 않는다.

### 3. 색상 — 4/4

- 확인 필요 황색, 실행 중 초록, 주요 행동 파랑이 역할별로 제한되어 있다.
- `npm run test:theme`은 다크·라이트 대표 화면과 908개 버튼 상태에서 테마 불일치 및 저대비 상태 0건을 확인했다.
- `npm run test:readability`에서 홈의 최소 대비는 4.96이며 검사 대상 전체에서 저대비 텍스트가 없었다.

### 4. 타이포그래피 — 4/4

- 큰 홈 문장은 사용자의 현재 판단을, 20–22px 섹션 제목은 실행 문맥을, 12–15px 본문·메타는 세부 상태를 담당한다.
- 자동 가독성 검사에서 12px 미만 텍스트, 겹침, 혼잡 그룹이 모두 0건이다.
- 데스크톱과 모바일에서 제목 줄바꿈이 의도된 문장 단위로 유지된다.

### 5. 간격·반응형 — 4/4

- `--intent-content: 1360px`, `--sidebar: 232px`, 44px 상호작용 높이로 넓은 화면의 밀도와 조작성을 함께 확보한다.
- 390px 모바일 홈은 보조 툴바를 전용 화면으로 넘겨 첫 에이전트를 스크롤 시작점에 완전히 노출한다.
- control-room, responsive, readability 검사에서 가로 넘침·클리핑·접근 불가능한 열린 본문이 없다.

### 6. 경험 설계 — 4/4

- `renderer/app-graph-view.js:628`의 첫 프로젝트 기본 펼침으로 앱 목표인 에이전트 시각화를 즉시 보여준다.
- 사용자가 닫거나 모두 펼치는 상태는 disclosure 저장 계약과 제어 상태를 유지한다.
- 서브에이전트, 실행 작업, 대화, 생명주기, 터미널, tmux의 상호작용이 3회 전수 검사에서 필수 누락 0건으로 통과했다.
