# 스케치 007: Project to Terminal Story

## 디자인 질문

사용자가 메인에서 진행 중인 프로젝트를 찾고, 프로젝트 안의 실행 중 세션을 선택한 뒤, 같은 PTY 터미널에서 진행 상황을 확인하고 답변할 때까지의 흐름이 자연스럽게 이어지는가?

## 장면

1. **메인 — 프로젝트 발견**: 전체 프로젝트 중 `Lodestar`가 `실행 중 2 · 답변 필요 1` 상태임을 발견한다.
2. **프로젝트 — 세션 선택**: Lodestar의 실행 중 세션, 에이전트, 경과 시간, 마지막 출력을 확인한다.
3. **실행 중 세션 — 터미널 복귀**: 별도 상세 드로어나 채팅 화면 없이 실행 중이던 PTY와 scrollback으로 바로 들어간다.
4. **답변 필요 — 같은 자리에서 재개**: 메시지 전달·연결 상태와 에이전트가 멈춘 이유를 확인하고 터미널 입력으로 답한다.

## 표현 방식

- **클릭 안내**: 각 장면의 다음 클릭 대상과 장면의 역할을 주석으로 표시한다.
- **앱만 보기**: 동일 장면에서 스토리 주석을 숨겨 실제 화면 밀도를 확인한다.

## 공통 연결 요소

- 네 장면 모두 같은 전역 레일, 프로젝트 색상, 프로젝트 경로를 유지한다.
- 메인에서 프로젝트로 들어가면 왼쪽 Lodestar 항목이 펼쳐지고 실행 중 세션이 나타난다.
- 세션 화면은 터미널이 본문을 전부 소유하며 별도의 웹 채팅 입력을 두지 않는다.
- 답변 필요 상태는 전역 배지, 프로젝트 배지, 세션 상태, 터미널 질문을 동시에 갱신한다.

## 보는 방법

`index.html`을 브라우저에서 열고 상단의 `01`부터 `04`까지 누른다. 화면 안의 강조된 프로젝트와 세션을 직접 눌러도 다음 장면으로 이동한다. 04에서 터미널에 답을 입력하면 같은 PTY에서 03의 실행 상태로 돌아간다.

## 확인할 것

- 메인 화면에서 클릭할 프로젝트가 즉시 보이는가?
- 프로젝트 화면에서 통계보다 실행 중 세션이 먼저 읽히는가?
- 세션 클릭 후 기존 작업이 끊기지 않고 그대로 이어진다고 느껴지는가?
- 응답이 늦을 때 메시지 전달 여부, PTY 연결 여부, 필요한 답이 동시에 보이는가?
