# 스케치 004: Intent Lineage

## 중심 명제

**AI의 답변이 아니라, 일이 이루어지는 과정을 보여준다.**

화면의 가장 작은 단위는 세션이나 모델이 아니라 `의도 → 해석 → 위임 → 행위 → 증거 → 판단`의 관계다.

## 제품 철학

1. 모든 행위는 인간의 의도로 돌아갈 수 있어야 한다.
2. 에이전트는 모델 이름보다 맡은 역할로 먼저 보인다.
3. PowerShell은 로그가 아니라 에이전트의 말이 현실에 닿는 행위다.
4. 결과는 완료 배지가 아니라 처음의 의도에 돌아온 증거다.
5. 인간의 주의는 정상 진행이 아니라 불확실성이 있는 곳에만 사용한다.
6. 세션은 끝나지만 인과의 기억은 남는다.

## 변형

- **A · 의도의 계보** — 여러 활성 작업을 목적 문장으로 시작하는 병렬 인과선으로 표현한다. 가장 읽기 쉽고 현재 제품 구조와 연결 가능해 추천한다.
- **B · 에이전트 성좌** — 인간의 의도를 중심에 고정하고 모든 에이전트와 실행을 기여 관계로 배치한다. 철학성은 가장 강하지만 세션이 많을 때 비교가 어렵다.
- **C · 인과 장부** — 모든 위임·명령·증거를 변경 불가능한 시간순 기록처럼 보여준다. 신뢰와 감사 가능성은 가장 강하지만 실시간 관제성이 약하다.

## 기존 기능의 새 언어

| 기존 기능 | 철학적 명칭 | 의미 |
|---|---|---|
| 홈 | 지금 | 살아 있는 의도만 관찰 |
| 전체 작업 | 기억 | 완료·중단된 인과 기록 |
| 확인할 일 | 판단 | 인간만 결정할 수 있는 경계 |
| 터미널·tmux·예약 | 도구 | 의도를 현실에 작용시키는 수단 |
| 새 작업 | 새 의도 | 무엇을 시킬지보다 왜 필요한지에서 시작 |
| 결과 | 증거 | 처음의 의도가 충족됐는지 검증 |

## 기억 페이지

`기억`은 완료된 세션 목록이 아니라 인과 기록과 재사용 가능한 판단의 공간이다.

- 각 기록은 원래 의도, 에이전트 위임, 실제 명령, 돌아온 증거를 한 줄로 보존한다.
- 완료 기록에서 반복된 판단을 `기억에서 남은 지혜`로 추출한다.
- 검색은 세션명뿐 아니라 의도·에이전트·명령·증거 전체를 대상으로 한다.
- 기록을 열면 “왜 존재했는가 / 무엇을 바꿨는가 / 어떤 증거가 남았는가”를 다시 읽는다.

## 추천

첫 구현은 **A · 의도의 계보**를 권한다. 현재 세션·서브에이전트·PowerShell 데이터를 유지하면서도 화면의 첫 문장을 작업명이 아닌 목적 문장으로 바꾸기 때문이다.
