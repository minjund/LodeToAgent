# 스케치 006: Terminal-first Agent Session

## 디자인 질문

메시지 응답이 늦거나 에이전트가 도구를 실행하는 동안에도 세션이 끝난 것처럼 보이지 않게 하면서, 사용자가 터미널 자체에서 대화와 명령을 이어갈 수 있는가?

## 공통 원칙

- 터미널과 PTY가 대화, 실행, 연결 상태의 원본이다.
- 별도 웹 채팅 입력창은 만들지 않는다. 화면 아래 입력부도 동일 PTY에 쓰는 터미널 입력 영역이다.
- 세션 목록과 구조화된 대화·작업 보기는 원본을 바꾸지 않는 탐색·투영 계층이다.
- 에이전트가 응답 중인지, 입력을 기다리는지, 중단됐는지를 터미널 상단에서 계속 보여준다.
- 재연결 시 scrollback과 현재 세션 문맥을 복원해 “그냥 끝난 것처럼” 보이는 공백을 없앤다.

## 변형

- **A · 순수 터미널** — 에이전트 탭과 상태선 외에는 터미널에 최대 공간을 준다. 가장 Orca에 가깝고 구현도 단순하다.
- **B · 세션 레일** — 프로젝트 안에서 여러 에이전트를 자주 오갈 때만 왼쪽 세션 레일을 상시 둔다. 터미널은 계속 주 작업면이다.
- **C · 대화 투영** — 터미널 오른쪽에 읽기 전용 대화·작업·컨텍스트 보기를 둔다. 비개발자 가독성은 높지만 화면 밀도가 커진다.

## 비교 기준

| 기준 | A · 순수 터미널 | B · 세션 레일 | C · 대화 투영 |
|---|---|---|---|
| 터미널 집중도 | 가장 높음 | 높음 | 중간 |
| 여러 세션 전환 | 탭 중심 | 가장 빠름 | 빠름 |
| 진행 과정 이해 | 원본 그대로 | 원본 그대로 | 구조화 보조 |
| 작은 화면 | 가장 유리 | 레일 접기 필요 | 투영 패널 접기 필요 |
| 권장 사용자 | 터미널 친화 사용자 | 병렬 작업 사용자 | 혼합 숙련도 팀 |

## 동작하는 항목

- A/B/C 레이아웃 전환
- 터미널 입력에서 Enter로 동일 PTY 전송 시뮬레이션
- 세션·에이전트 탭 전환과 scrollback 복원 표시
- 실행 중단, PTY 재연결, 터미널 수평 분할
- C안의 대화·작업·컨텍스트 투영 전환 및 패널 닫기
- 375/768/1280 반응형 미리보기, 밝은 테마, 설계 주석

## 보는 방법

`index.html`을 브라우저에서 열고 상단의 A/B/C 탭을 눌러 비교한다. 하단 터미널 입력에 메시지를 쓰고 Enter를 누르면 원본 PTY에서 대화가 이어지는 흐름을 확인할 수 있다.

## 현재 추천

기본은 **A**로 시작하고, 프로젝트 내 동시 세션이 두 개 이상일 때 **B의 세션 레일을 토글로 여는 조합**을 권한다. **C는 기본 화면이 아니라 필요할 때만 여는 읽기 전용 보조 패널**로 두는 편이 터미널 중심 원칙을 보존한다. 최종 선택은 사용자 비교 후 기록한다.
